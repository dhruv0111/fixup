# Phase 5 sales APIs

All responses use `{data}` or `{error}` and private/no-store caching. Auth uses existing Better Auth sessions and current database roles. JSON writes require the exact configured Origin and application/json; strict schemas reject browser prices/category overrides. Request body limit is 16 KiB. No payment gateway or money transfer API exists.

| Method/path under `/api/v1`         | Access and behavior                                                                                                                                                          |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET `me/cart`                       | Own active customer/dealer cart with recalculated current category prices and free stock                                                                                     |
| PATCH `me/cart`                     | `{variantId,quantity}` absolute quantity 1–10,000; zero removes; maximum 50 variants                                                                                         |
| POST `me/checkout/preview`          | `{addressId,paymentMethod:"UPI"\|"BANK"}`; own saved address, current prices, confirmed rules, payer instructions and signed `reviewToken`                                   |
| GET `me/orders`                     | Own latest 200 orders and explicit public DTO only                                                                                                                           |
| POST `me/orders`                    | `{requestId:UUID,addressId,paymentMethod,reviewToken,notes?}`; atomic reviewed checkout, reservations and cart clear; same request/data replays the order                    |
| GET `me/orders/:id`                 | Own order details, timeline, receipts and proof metadata; applies due expiry safely                                                                                          |
| POST `me/orders/:id`                | `{action:"CANCEL",version,reason,internalNotes?:""}`; configured snapshotted unpaid cancellation policy                                                                      |
| POST `me/orders/:id/payments`       | Own multipart `{requestId,method,reference,paidOn:YYYY-MM-DD,remarks?,file}`; PNG/JPEG/WebP ≤5 MiB, ≤16 million pixels, actual decode/re-encode; one pending proof per order |
| GET `payments/:id/proof`            | Owner or payments.verify; private PNG stream, no-store, nosniff, sandbox; no image optimizer                                                                                 |
| GET `admin/sales/orders`            | orders.manage; `q,status,paymentStatus,from,to` filters; 200 latest matches                                                                                                  |
| GET `admin/sales/orders/:id`        | orders.manage; complete details, internal notes, bank verification history                                                                                                   |
| POST `admin/sales/orders/:id`       | orders.manage; `{action,version,reason,internalNotes?}`; CANCEL, NOTE, RESOLVE_LATE, RESOLVE_OVERPAYMENT, REFUND_DECISION                                                    |
| GET `admin/sales/payments`          | payments.verify; latest 200 proofs across orders                                                                                                                             |
| POST `admin/sales/payments/:id`     | payments.verify; `{action,version,reason,internalNotes,publicMessage?}`; REVIEW, REJECT, RESUBMISSION_REQUIRED, VERIFY                                                       |
| POST `admin/sales/refunds/:orderId` | payments.verify; completed external refund recording only                                                                                                                    |
| GET/POST `admin/sales/settings`     | settings.update (SUPER_ADMIN); all settings require explicit confirmation and current version                                                                                |
| POST `admin/sales/expire`           | orders.manage, same-origin JSON `{}`; safe idempotent batch of up to 100 due orders                                                                                          |

Verification additionally requires `requestId:UUID,checkedBankRecord:true,amountPaise,bankReference`; flagged duplicates require `duplicateReviewed:true`. Repeated identical verification returns the existing receipt. A globally unique canonical actual bank reference prevents crediting a transaction twice across orders or methods. Admins cannot verify/review their own customer order. Internal notes never enter customer DTOs. Original proofs, order snapshots, lines, verified receipts/refunds and reservation events cannot be rewritten or deleted.

Refund recording requires `requestId,method,amountPaise,bankReference,checkedBankRecord:true,reason,internalNotes`. The refund must already have been completed externally and independently checked. It cannot exceed verified net funds for a cancelled order, or the excess for an active overpaid order. It never initiates a transfer. A cancelled paid order retains verified receipts and a refund-decision flag until an explicit decision or completed refund is recorded.

Settings fields: `version,enabled,confirmed:true,reason,upiId,holderName,bankName,accountNumber,ifsc,branch,instructions,taxBps,taxMode,deliveryPaise,reservationMinutes,lateReviewMinutes,customerCancelUnpaid,adminCancelUnpaid,adminCancelPaid`. Tax mode is INCLUSIVE or EXCLUSIVE, basis points 0–10,000; delivery is integer paise; durations are explicit minutes, near-expiry window no greater than reservation duration. Cancellation flags must be explicit booleans. At least a valid UPI ID or complete bank details are required to enable ordering. No real settings are seeded.

Reservation expiry: trusted server operators can run `npm run orders:expire -- --confirm-expire`. It reads the configured server environment, processes at most 100 orders, logs counts only and exits. Repeat until `expired:0`. A scheduler is not configured; production operators must arrange periodic execution with private server credentials. Full, timely verified payment holds stock without expiry pending review/dispatch. Late or near-expiry proof never restores stock; RESOLVE_LATE rechecks available stock and explicitly re-reserves expired holds. Cancelled/released holds cannot be restored. Phase 5 rejects consumption and dispatch.

Order statuses: PENDING_PAYMENT, PAYMENT_UNDER_REVIEW, PAYMENT_REJECTED, ADMIN_REVIEW, READY_FOR_DISPATCH, CANCELLED, RESERVATION_EXPIRED. Payment status: UNPAID, PARTIALLY_PAID, PAID, OVERPAID; verified net receipts minus recorded refunds and remaining amount are displayed separately. Submission status: SUBMITTED, UNDER_REVIEW, VERIFIED, REJECTED, RESUBMISSION_REQUIRED; no submission is displayed as Not submitted. History is an in-app notification; no external delivery is claimed.
