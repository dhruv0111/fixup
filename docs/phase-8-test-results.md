## Failure root causes, fixes and reruns

1. **Sandbox database/registry access:** PostgreSQL migration connectivity and npm advisory DNS failed under restricted execution. Retried those exact classes of checks with authorized local/network access. No database reset, validation bypass or test skip was used.
2. **Stale generated client:** initial TypeScript errors included missing dispatch/report models because ignored Prisma generation output was stale while checks began. Regenerated from the committed schema; subsequent typecheck and the production build passed. Application types were preserved.
3. **Production catalogue test setup:** subprocess supplied HTTPS/SMTP mode but omitted the explicit valid `MAIL_FROM` required by existing environment validation. Added only a dummy sender to that subprocess and an assertion for its successful completion message. It queries catalogue visibility and sends no email. The affected run executed and passed the case and both catalogue browser suites.
4. **FIN-01 actual versus selected method:** actual receipt/refund/submission queries reused an order filter that included checkout method. The added test first failed with an uploaded BANK proof reported as zero because checkout selected UPI. Removed checkout-method restriction only from the payment/submission relation filter; kept entity filtering, actual record method filtering and original created-order cohort semantics. The post-fix test passed pending workload, bank receipts, a bank refund against a UPI receipt, net bank collections and separate UPI totals. All Phase 7 API and both viewport suites passed afterward. Approved metric documentation now makes the distinction explicit.
5. **Integrity scan anomaly:** the scan found one synthetic order with recorded subtotal/total 20,000 paise and line subtotal 20,100 paise. Read-only investigation found its original two-unit line plus `QA unreserved line` (100 paise), matching `tests/integration/phase6.spec.ts`'s **missing reservation** negative case. That test intentionally inserts the extra line directly through the privileged test client and asserts the HTTP dispatch attempt is rejected with no dispatch created; it passed in the full run. This malformed fixture is retained, not repaired, deleted or counted as a clean global scan. No comparable API-created arithmetic failure was demonstrated. Direct database/operator access must remain restricted (SEC-02).

Observed development-server diagnostics included NO_COLOR/FORCE_COLOR warnings, a pg query-concurrency deprecation, expected sanitized fault-injection events, and two generic destination-stream errors during browser navigation. They did not produce additional assertion failures or secret-bearing API output in this run. Production logging/monitoring and future dependency-upgrade behavior still need staging verification.
