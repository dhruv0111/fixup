## Minimal monitoring plan — not deployed

Use the chosen host's existing health checks, log collection and notification features first. Name an alert owner and backup contact. Proposed initial rules for owner review:

- Probe readiness every minute; alert on two consecutive failures. Also probe liveness to distinguish DB/application failure. Check response cache behavior through the actual proxy.
- Alert on sustained unexpected 5xx responses, DB connection/pool timeouts, and reservation-expiry job failure/backlog. Start with five unexpected failures in five minutes, then tune against staging traffic.
- Track payment verification and dispatch routes separately for unexpected errors and unusual rejection/conflict rates. A rejected or duplicate proof must never be counted as received money. Monitoring must not retry a financial mutation with a new request ID.
- Alert immediately on backup failure, a missed backup window, restore-drill failure, MFA lockout spikes and privileged account/session changes. Prove notifications reach the assigned people.
- Retain request ID, timestamp, route pattern, status and bounded failure category. Exclude passwords, cookies, reset/verification URLs, TOTP/setup/recovery codes, DB URLs, upload bytes and raw request bodies. Review proxy logs too.

The existing protected `orders:expire -- --confirm-expire` command is bounded to 100 orders per invocation. Schedule and monitor it privately, prevent overlapping writers and repeat until zero. No public cron endpoint is required. Its scheduler and alert delivery remain NOT VERIFIED.

## Release/rollback prerequisites

Select and review an immutable commit/build, intended Node runtime and environment configuration; this workspace has pre-existing uncommitted work. Rehearse migrations with the migration role and take a verified encrypted backup first. Keep the previous security-compatible artifact/config and migration compatibility record. A pre-MFA artifact is not an acceptable public rollback merely because it starts.

For a fault: gate writes/traffic/jobs, preserve evidence, assess artifact/schema compatibility, and obtain the incident owner's decision. Restore only to a fresh isolated DB, verify it, revoke restored auth state and reconcile later business events before a separately approved switch. Do not automatically reverse migrations, reset data, replay payments or disable MFA. Hosting creation, external validation and deployment each require explicit approval; this checklist grants none.
