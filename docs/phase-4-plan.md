# Phase 4 pre-implementation audit and plan

13 November 2026. Reviewed repository/source tree, original PRD and Phase 1–3 reports, schema/six migrations, variant catalogue, Better Auth/current-role permissions, admin workspace/forms, audit/history, request guards, isolated DB runner, and integration/browser tests. Existing uncommitted Phase 3 work is preserved. No supplier/purchasing/inventory runtime exists yet. No critical existing architectural blocker identified; inventory consistency must be added as an explicit boundary.

1. Add additive supplier, purchase order/line, GRN/line, stock lot/movement, adjustment and minimum-threshold models. Retain the existing QWIK parent and four variant IDs.
2. Suppliers: protected create/edit/search/status, optional validated GSTIN and duplicate identity protection, supplied-variant links and historical purchase access. No delete endpoint.
3. POs: versioned drafts, server-calculated integer-paise line discounts and tax basis points, immutable submitted snapshots, unique sequence-backed numbers, explicit submit/cancel. Only submitted/partially received orders may receive.
4. GRNs: editable drafts, quantities checked again on confirmation, multiple partial receipts, exactly-once confirmation and super-admin reversal only while the received lot remains wholly available. Cancellation of drafts has no stock effect.
5. Stock: append-only ledger is the source of truth; balances/lot remainders are sums, never mutable totals. A DB trigger serializes by variant, verifies both lot and variant balances and sets before/after values; rejects negatives and ledger edits/deletes. Per-PO transaction locks serialize receiving and PO transitions. Idempotency keys reject altered retries and preserve safe repeated requests.
6. Adjustments: explicit confirmation, mandatory reason, opening/physical correction/damage/missing/other, independent variant/lot references. Damage transfers available to damaged quantity; no reservation or return-to-supplier workflow in this phase.
7. Batch/date metadata is optional and supplied by admins, with date ordering validation; no invented shelf-life/expiry computation. Thresholds are optional per variant; no invented reorder quantity.
8. Extend the existing admin workspace with suppliers, PO/GRN editors/details, stock/ledger/adjustment pages, filtered reports and protected CSV exports. Admin and Super Admin manage operations; only Super Admin reverses completed receipts. Sales/customer/dealer roles receive no new internal access.
9. Add unit/API/desktop/mobile coverage for happy paths, negative quantities/tampering, duplicate/concurrent receiving, rollback, immutable ledger, batch traceability, reports/CSV, authorization and the original full regression suite. Run validation/migrations/schema diff/recovery, TypeScript/lint/format, build/smoke and screenshots. Record exact executed outcomes.

Business defaults disclosed: single stock location; integer units per variant; INR integer paise; line discount is a fixed amount, tax is explicit basis points applied after discount and rounded half-up per line. Monetary totals are limited to 2,000,000,000 paise per PO to fit checked integer storage. These are calculation/input conventions, not invented tax rates, purchase prices or supplier terms. Opening stock is allowed once per variant; subsequent changes use correction/other operations. Negative available or damaged stock is prohibited.

No checkout, payments, sales orders, automatic reservations, supplier returns, warehouse transfers, dispatch, dealer credit, production deployment or Phase 5 work. Final execution report follows actual verification; no advance completion claim.
